# TBD: 推特书签归档系统 (Twitter Bookmarks Depot)

一个稳健的、自托管的推特 (Twitter/X) 书签同步、归档与本地浏览系统。

[English](./README.md) | **中文文档**

**TBD** 最初只是一个简单的 **书签下载器 (Downloader)**，现在已经进化为您的个人 **推特备份守护进程 (Backup Daemon)**，并致力于成为您本地媒体收藏的终极 **数据仓库 (Depot)**。

## 为什么选择 TBD？

大多数下载工具要么依赖昂贵的官方 API（限制多），要么依赖脆弱的爬虫库（容易失效或导致封号）。

**TBD** 采用了一种完全不同的架构：**被动拦截 (Passive Interception)**。

它运行一个本地服务器，并配合浏览器用户脚本（Userscript），直接拦截并转发浏览器从推特获取的*原始数据*。这意味着：

- **无需 API Key**：只要您能在浏览器里看到，TBD 就能保存。
- **无视速率限制**：完全模拟真实用户行为，零封号风险。
- **全保真数据**：不仅保存媒体文件，还完整保存原始的 GraphQL JSON 响应和元数据。
- **安全隐私**：所有操作均在您已登录的浏览器会话中进行，数据只存在您的本地硬盘。

## 核心特性

- **🔄 自动同步**：在推特书签页增加“自动滚动”按钮，一键挂机抓取所有历史书签。
- **📹 媒体守护**：后台 Worker 自动多线程下载最高画质的图片和视频，**智能跳过已下载文件**。
- **🕰️ 时间线保真**：下载文件的修改时间会被设置为**推文的原始发布时间**，确保您在文件管理器中按时间排序时能还原真实的历史时间轴。
- **🗄️ SQLite 存储**：高效去重，结构化存储，便于未来检索。

* **🛡️ 原始数据归档**：完整保留原始 JSON 负载，为未来的数据恢复或分析留足后路。
* **🧠 智能 & 强力模式**：
  - _智能模式 (Smart)_：遇到已保存的书签自动停止，适合日常增量同步。
  - _强力模式 (Force)_：无视重复持续滚动，适合填补历史数据的缺失漏洞。
* **🔧 极强抗干扰**：多层解析策略（结构体匹配 + 正则兜底），即使推特微调 API 结构也能正常工作。

## 架构原理

1.  **前端 (Userscript)**：运行在 `x.com` 页面上（通过 Tampermonkey）。它 Hook 了浏览器的 `XMLHttpRequest`，静默捕获书签数据，并通过 `GM_xmlhttpRequest` 将其推送到本地服务器。
2.  **后端 (Go)**：一个轻量级的 HTTP 守护进程 (`:41008`)。它负责解析复杂的 GraphQL 响应，管理 SQLite 数据库，并处理繁重的媒体下载任务。

## 安装指南

### 1. 后端 (Go)

请确保已安装 [Go](https://go.dev/dl/) (1.20+)。

```bash
# 克隆仓库
git clone https://github.com/rainux/twitter-bookmarks-downloader.git tbd
cd tbd

# 编译
go build -o tbd .

# 启动服务
./tbd
```

服务器将在 `localhost:41008` 启动监听。

### 2. 前端 (用户脚本)

1.  在浏览器（Chrome/Edge/Firefox）中安装 **Tampermonkey** 扩展。
2.  创建一个新脚本。
3.  将项目中的 `sync-bookmarks.user.js` 内容复制并粘贴进去。
4.  保存并启用脚本。

## 使用方法

1.  **启动后端**：保持 `./tbd` 在终端运行。
2.  **打开推特**：在浏览器访问 **[Twitter Bookmarks](https://x.com/i/bookmarks)** 页面。
3.  **使用控制面板**：查看左下角的悬浮面板。
    - 点击 **▶** 开始自动滚动。页面将自动下翻，后端开始接收并保存推文。
    - 点击 **∞** 切换 **强力模式 (Force Mode)**：如果您想强制扫描历史数据或修复缺失，请开启此模式。
4.  **查看结果**：
    - 终端日志会显示 "Saved X new tweets"。
    - 图片和视频会自动下载到 `media/` 目录。
